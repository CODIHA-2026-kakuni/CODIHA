# 概要

このアプリは，千葉市内での，リサイクル回収ボックスの位置を表示する．
使用する言語は，`javascript`，`node`，`Express`，`HTML`，`CSS`である．

# 機能仕様

- ユーザーの現在地から，回収ボックス設置場所までの，直線距離の計算を行う
- ゴミの一覧をソートせずに表示する．
- ゴミのデータは，`MySQL`，`SQLite3`または，`json`でデータベース管理をする．
- 特定の場所に持ち込む必要がある場合は，その場所を現在地から距離の近い順に一覧表示する．
- ユーザーは，候補地をクリックすると，その場所がGoogleマップで表示される．
- 候補地は，リストとGoogleマップの両方で表示される．レイアウトは，リストが下，Googleマップが上に表示される．
- ユーザーは，ゴミの一覧が50音順で表示される．
- ユーザーは，検索ボックスを使うことで，ゴミの品目を検索できる．

# SQLite3・MySQL・jsonの比較

データ管理方式として，`SQLite3`，`MySQL`，`json`の3つが候補となる．それぞれの概要とメリット・デメリットを以下にまとめる．

## SQLite3

### 概要

SQLite3は，サーバーを必要としない軽量なリレーショナルデータベース管理システム（RDBMS）である．データベース全体が1つのファイルとして保存され，アプリケーションに組み込んで利用する．

### メリット

- サーバーの構築・管理が不要で，導入が容易である．
- SQL文による検索・絞り込み・並び替えといった操作を実装しやすい．
- ある程度多量のデータでも高速に検索できる．
- トランザクション管理により，データの整合性を保ちやすい．
- ファイル1つで完結するため，バックアップや配布が容易である．

### デメリット

- 複数ユーザーからの同時書き込みには弱く，大規模な同時アクセスには向かない．
- ネットワーク越しの利用を想定していないため，複数サーバーでの共有には不向きである．
- 大規模なデータ量やアクセス数になった場合，MySQLなどの本格的なRDBMSに比べて性能面で劣る．

## MySQL

### 概要

MySQLは，クライアント・サーバー型のオープンソースRDBMSである．データベースサーバーを別途構築し，ネットワーク経由でアクセスする方式を取る．

### メリット

- 複数ユーザー・複数アプリケーションからの同時アクセスに強い．
- 大量のデータや高いアクセス数にも対応できるスケーラビリティを持つ．
- ユーザー権限管理やレプリケーションなど，運用面の機能が充実している．
- 広く使われているため，情報や事例が豊富である．

### デメリット

- サーバーの構築・設定・保守が必要であり，導入コストが高い．
- 小規模なアプリケーションには機能が過剰であり，運用の手間に見合わない場合がある．
- ネットワーク経由でのアクセスとなるため，構成によっては通信遅延が発生する．

## json

### 概要

jsonは，軽量なデータ交換用のテキストフォーマットである．データベース管理システムではないが，ファイルとしてデータを保存し，プログラムから読み書きする形で簡易的なデータ管理に用いられる．

### メリット

- 人間が読み書きしやすいシンプルな構造である．
- 多くのプログラミング言語で標準的にサポートされており，扱いやすい．
- サーバーやライブラリの追加導入が不要で，すぐに利用を始められる．
- データ構造が単純な場合，実装が非常に容易である．

### デメリット

- データ量が増えると，読み込み・書き込みの速度が低下しやすい．
- 複雑な検索や絞り込み，集計といった操作を自前で実装する必要がある．
- 複数ユーザーからの同時書き込みに対する整合性の担保が難しい．
- データ件数が多くなるほど，ファイル全体を読み込む処理が非効率になる．
