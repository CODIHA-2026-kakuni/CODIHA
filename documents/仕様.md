# CODIHA 仕様書

## 1. 概要

CODIHA（ごみ分別・持込ナビ）は、千葉市のごみ品目を検索し、分別区分・出し方・注意事項を確認できるWebアプリケーションです。小型家電の回収対象品目では、対応する回収場所を地図と一覧で表示します。

## 2. 使用技術

- Node.js 20
- Express 5.2.1
- EJS 3.1.10
- MySQL 8.4
- mysql2 3.24.3
- Leaflet 1.9.4
- OpenStreetMap
- Docker Compose

## 3. 画面構成

### 品目検索画面 `GET /`

- MySQLに登録された2,058品目を読み仮名順で表示します。
- 検索語がある場合は、品目名または読み仮名の部分一致で絞り込みます。
- 全角・半角、英字の大文字・小文字、ひらがな・カタカナの違いを検索時に吸収します。
- 検索はExpress側で処理し、結果をEJSでHTMLとして返します。
- 品目を選ぶと`/result?itemId={id}`へ移動します。
- 該当なし、DB未登録、DB接続失敗をそれぞれ案内します。

### 結果画面 `GET /result?itemId={id}`

すべての品目で、品目名、分別区分、出し方、注意事項を表示します。注意事項がDBで空欄の場合は、その欄を表示しません。出し方が空欄の場合は公式ガイドの確認を案内します。

`battery`、`phone`、`other_electronics`のいずれかが`true`の品目だけ、位置情報の取得と回収場所表示を開始します。すべて`false`の品目では地図と施設一覧を表示しません。

- `itemId`の形式が不正：400
- `itemId`に対応する品目が存在しない：404
- DB取得失敗：500

## 4. 品目検索

品目はMySQLから取得し、Node.js側で検索用文字列を正規化して絞り込みます。SQLへ利用者の検索語を直接連結しません。

並び順は、読み仮名を`Intl.Collator('ja')`で比較し、同じ場合はID順です。検索後も入力した検索語を検索欄へ残します。

## 5. 回収場所API

### エンドポイント

```text
GET /api/items/:id/sites
GET /api/items/:id/sites?lat={緯度}&lng={経度}
```

### 処理

1. 品目IDと緯度・経度を検証します。
2. 品目の回収種別を確認します。
3. 同じ回収種別に対応する施設をMySQLから取得します。
4. 位置情報がある場合はHaversine式で直線距離を計算し、距離順で返します。
5. 位置情報がない場合は、区の固定順、その中で施設の読み仮名順に返します。

区の順番は次のとおりです。

```text
稲毛区 → 中央区 → 花見川区 → 緑区 → 美浜区 → 若葉区
```

距離はAPIで小数第3位まで返し、画面では小数第1位まで表示します。回収種別がない品目では`{ "sites": [] }`を返します。

## 6. 位置情報

回収場所を表示する品目の結果画面を開いた直後に、ブラウザのGeolocation APIを使用します。

- 高精度測位：使用しない
- タイムアウト：10秒
- キャッシュ許容：5分
- 保存：しない

取得できた場合は現在地をAPIへ一時的に送り、距離順で表示します。拒否、タイムアウト、非対応の場合は距離を表示せず、施設を区ごとに表示します。

## 7. 地図と施設一覧

- 画面内地図はLeafletとOpenStreetMapを使用します。
- 位置情報ありでは、現在地と番号付き施設マーカーを表示します。
- 位置情報なしでは、番号なし施設マーカーを表示します。
- 施設カードには施設名、住所、利用時間を表示します。
- 営業中・時間外は自動判定せず、DBの利用時間を文字列のまま表示します。
- 「地図で見る」は地図へスクロールし、対象施設をズーム16で中央表示して吹き出しを開きます。
- 「Googleマップで経路」は、施設の緯度・経度を目的地として別タブで開きます。

地図を読み込めない場合も施設一覧とGoogleマップは利用できます。施設APIの取得に失敗した場合は施設欄だけにエラーと再試行を表示し、品目情報は残します。

## 8. データベース

### `item`

品目名、読み仮名、分別区分、出し方、注意事項、持込要否と、3種類の小型家電回収フラグを保存します。

### `recycle_location`

施設名、読み仮名、区、住所、緯度・経度、利用時間と、3種類の受付可否を保存します。施設は30件です。

初回起動時のみ、MySQL公式イメージの初期化機能が`Application/SQL`内のSQLとCSVをファイル名順に実行します。Dockerボリュームに既存データがある場合、CSVを変更しても自動では再登録されません。

## 9. 画面確認用状態

UIだけを確認するため、次のURLを残しています。これらのURLでは通常の位置情報取得や施設API呼び出しを行いません。

```text
/?state=loading
/?state=empty
/?state=error
/result?state=loading
/result?state=empty
/result?state=error
/result?state=no-location
```

- 公式サイトからのデータ自動更新
- 位置情報の保存
